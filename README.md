# Интеграция Eloquent ORM и Monolog в PHP-приложение

Проект представляет собой скелет современного веб-приложения на языке PHP, развернутый в изолированном Docker-окружении на базе архитектуры WSL2. 

## Стек технологий
* **Язык программирования:** PHP 8.4-FPM
* **Веб-сервер:** Nginx (Alpine-образ)
* **СУБД:** PostgreSQL 15 (данные контейнера вынесены на физический диск D)
* **Менеджер зависимостей:** Composer 2
* **ORM:** Eloquent (`illuminate/database`)
* **Логирование:** Monolog (`monolog/monolog`)

---

##Архитектурные особенности и реализация

### 1. Работа с базой данных и ORM (Eloquent)
* Вместо написания «сырых» SQL-запросов интеграция с PostgreSQL выполнена через компонент **Eloquent ORM** фреймворка Laravel.
* В файле `src/database.php` инициализирован менеджер соединений `Capsule`, настроен глобальный доступ к ORM (`setAsGlobal`) и активирован движок моделирования (`bootEloquent`).
* Описана модель `User`, наследуемая от `Illuminate\Database\Eloquent\Model`, для объектного взаимодействия с таблицей пользователей.

### 2. Автоматические миграции
* Реализован механизм автоматического контроля структуры БД при каждом HTTP-запросе с помощью фасада `Capsule::schema()`.
* При первом запуске скрипт проверяет наличие таблицы `users`. Если таблица отсутствует, мигратор кодом создает её структуру (колонки `id`, `name`, `email`, `timestamps`) и автоматически наполняет демонстрационными данными.

### 3. Логирование HTTP-запросов и ответов (Monolog)
* Входной точкой приложения является файл `public/index.php`.
* Средствами библиотеки **Monolog** инициализирован логер с каналом `http_logger` и уровнем логирования `Level::Info`. Журнал событий пишется в файл `logs/app.log` через `StreamHandler`.
* **Перехват запроса:** В самом начале жизненного цикла приложения логер перехватывает глобальный массив `$_SERVER` и записывает метод и URI входящего запроса (например: `[GET] /`).
* **Логирование ответа:** В конце выполнения скрипта сгенерированное тело HTML-ответа очищается от тегов с помощью функции `strip_tags()`, форматируется и отправляется в лог-файл параллельно с выводом пользователю в браузер.

## Инструкция по локальному запуску

1. Убедитесь, что запущен **Docker Desktop** с включенной интеграцией WSL2.
2. Клонируйте репозиторий и перейдите в папку проекта.
3. Разверните контейнеры командой:
   ```bash
   docker compose up -d
   ```
4. Проект станет доступен в браузере по адресу: **http://127.0.0.1:8085**
5. Для просмотра файла логов выполните в консоли Ubuntu команду:
   ```bash
   cat logs/app.log
   ```
6. Для остановки контейнеров введите:
   ```bash
   docker compose down
   ```
